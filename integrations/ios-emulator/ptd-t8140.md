# T8140 PTD message transport

`ptd-t8140.c` adapts the shared `ptd-t8140.h` state machine to QEMU. This is a
functional transport between processors, not a replacement for PMP firmware.
It never inserts controller replies, power states, CPU-ready resources or
successful command acknowledgements. No Apple firmware or disassembled code
is distributed with it.

## Basis

The iPhone17,3 / d47ap iOS 27.0.1 / 24A446 firmware contains
`Firmware/pmp/t8140pmp.im4p`. Its SHA-384 matches the BuildManifest's PMP entry.
Reproduction identifiers:

* IM4P SHA-256: `16395c6c3f7b8b6222937d6e7d997d586317d7c89f56b812284e056d7f8906f5`
* Payload SHA-256: `86b139c4d58ac573385d41bf6595c729b68b1cf075dea0165ff66a0253192210`
* RTKit release: `3514.0.15`; ARM64 preload image entry: `0x1000000`.

The firmware's PTD device configuration at VM `0x1046950` points to the
register mapping at `0x1046930` (physical `0x3003c0000`, length `0x20000`)
and configuration at `0x1038d78` (**512 entries, 32 interrupt outputs**).
These values come from this firmware, not an inferred dashboard-view size.

Its built-in tests at `0x101d17c` and `0x101d334` specify the message behavior:
write a value, observe pending, read value/metadata, check the timestamp and
`new_data`, and distinguish a dropped unread value when a second write replaces
it. A write of zero is still a message. The test at `0x101d440` programs routing
and masks, then checks interrupt delivery; handler `0x101d644` acknowledges an
entry by reading its pair. The pair reader is at `0x101ce18`; initialization
at `0x101cee8` clears entries through update writes followed by pair reads.
These routines were analyzed, not used as a replacement controller. The
[isolated PMP machine](pmp-research.md) executes the original firmware, which does not
reach these PTD tests there.

The matching ApplePMGR driver corroborates these semantics: unslid
`0xfffffff0092e29bc` programs routing; `0xfffffff0092e2aec` and
`0xfffffff0092e2b6c` enable/disable notifications; `0xfffffff0092e2bec` reads
the pair, `0xfffffff0092e2c64` writes a message and `0xfffffff0092e2ca0` reads
pending bits. The device tree selects PTD driver version 1.

## Register contract

Offsets below are relative to physical `0x3003c0000`.

| Register | Width | Behavior |
| --- | --- | --- |
| `entry * 16` | 64 bits | Read current payload for entry 0–511; does not consume it |
| `entry * 16 + 8` | 64 bits | Read metadata and consume its new/dropped flags; retains payload and timestamp |
| `0x10000 + entry * 8` | 64 bits | Write entire payload; set new-data, set dropped if a previous message was still unread, sample the CPU physical counter |
| `0x18000 + word * 4` | 32 or aligned 64 bits | Read raw pending bits, independent of interrupt enable; 16 words; reads do not acknowledge |
| `0x18200 + word * 4` | 32 bits | Write-one-to-enable; 16 words |
| `0x18300 + word * 4` | 32 bits | Write-one-to-disable; 16 words |
| `0x18400 + (entry / 8) * 4 + ((entry / 4) % 2) * 0x200` | 32 bits | Four eight-bit routing fields per word; low five bits of each select one of 32 outputs |

Metadata bit 1 means new data, bit 0 means dropped unread data. Bits 63:10
contain a 54-bit counter sample. Bit 0 is **not a validity flag**. Reading
metadata returns the pre-consumption flags, then clears pending/new/dropped.
The original pair load executes as two 64-bit QEMU device transactions; the
model consumes on the metadata transaction. Exact physical snapshot/latching
timing and concurrent access from a second processor remain unqualified.

Interrupt outputs are the OR of pending, enabled entries assigned to each
line. Disabling an entry masks its notification without discarding pending
data. Rerouting an enabled pending entry lowers its former line unless another
entry still needs it, and asserts its new line. Consuming one message cannot
acknowledge another entry sharing the output. Timestamp sampling uses the
same virtual clock and frequency as the ARM CPU physical counter, including
guest pause behavior; host wall-clock time is not used.

Reset produces an empty transport, zero routes and disabled notifications as
**explicit emulator boot policy**, not a measured silicon/iBoot snapshot.
Any controller status must come from a controller implementation. No command
sequence number is echoed into a reply entry.

Unsupported offsets, invalid widths, reserved routing bits, dashboard writes,
update reads and enable/disable reads return `MEMTX_DECODE_ERROR`. Invalid
transactions leave state intact. Eight-byte routing stores are not split into
two accepted four-byte writes. Unaligned guest device accesses can raise an
architectural alignment fault before reaching the model.

## Integration and limits

`-machine darwin,research-mcc=on,research-ptd=on` requires the validated T8140
MCC binding and exact PTD dashboard/update register indices and ranges. The
original PMP nub must select `ptd-driver-version=1`. The
CPU must be realized before its physical-counter link is installed. The
device maps a `0x20000`-byte window; unsupported portions still fault.

All 32 output lines are implemented and tested in `tomacco-ptd-test`. The
Darwin platform's actual SoC interrupt connection is **not yet qualified**.
With `irq-connected=false` (the Darwin default), a nonzero enable write
therefore faults without changing state. Accepting an enable that could not
reach its consumer would conceal a missing platform dependency. The test
machine connects these outputs to QTest's interrupt observer. Migration is
explicitly unavailable.

The Rust inspector advertises `ptd_mailbox` and `ptd_mmio_trace` independently
from machine/trace help. Only `exclave-mcc` enables the transport when the
selected engine provides it. Engines without it retain their previous MCC
behavior; other research profiles do not receive a PTD option. The managed
report preserves the actual command and engine capabilities. The trace event
`tomacco_ptd_mmio` records direction, offset, value, width and supported status,
capped at 1,024 events per reset.

PMP execution is separate, in the isolated research machine. The Darwin guest has no running PMP controller; the mailbox command protocol,
power transitions, complete PMGR/MCC initialization and graphical iOS remain
unavailable.

## Reproducible checks

```sh
python3 -m unittest discover -s tests/python -p test_ios_ptd.py -v
python3 tests/ios_ptd_integration.py \
  --engine .tooling/ios-sptm/build/qemu-system-aarch64 \
  --clang /absolute/clang --linker /absolute/ld.lld \
  --output /absolute/ptd-results.json
```

The shared production core runs with undefined-behavior sanitization. The
QEMU test covers all 512 messages and routing fields, 32 interrupt outputs,
masked pending data, overlapping notifications, rerouting, zero overwrites,
consumption and reset. Its original ARM64 guest checks timestamps against
CNTPCT, performs pair reads and verifies that 13 invalid operations raise
external aborts while two unaligned accesses fault architecturally. Rejected
partial reads never acknowledge the message, and rejected writes preserve
state. Tracing on/off yields identical guest assertions. None of these checks
requires Apple binaries or qualifies a graphical iOS runtime.
